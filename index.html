WHAT IS TP?

TP Middleware

Transaction Processing

TP(Transaction Processing) 미들웨어는 여러 사용자의 요청을 안정적으로 처리하고 서버와 서비스 사이의 트랜잭션을 관리하는 핵심 시스템입니다.

WEB → WAS → TP → DB

CORE RESPONSIBILITIES

주요 업무

TP 시스템의 안정적인 운영을 위해
다음과 같은 업무를 수행합니다.

01

장애 대응 및
원인 분석

TP 서버 Boot 실패, Core Dump, 로그 분석 및 서비스 응답 지연과 Timeout 원인을 분석합니다.

  • Boot 실패 분석
  • Core Dump 분석
  • ULOG · SLOG · TMLOG
  • Timeout 분석
02

서비스 배포 및
운영

서비스가 안정적으로 운영될 수 있도록 신규 서비스 등록과 서버 및 Binary를 관리합니다.

  • 신규 서비스 등록
  • 서버 추가
  • Binary 배포
03

성능 관리

시스템 자원과 서비스 응답 상태를 지속적으로 확인하고 성능 저하 원인을 분석합니다.

  • CPU · Memory
  • 프로세스 상태
  • 응답시간
  • 병목 분석
04

시스템 점검

정기적인 시스템 점검을 통해 운영 환경을 안정적으로 유지하고 필요한 작업을 수행합니다.

  • 디스크 용량 확인
  • 로그 정리
  • Backup 확인
  • Patch · 재기동
05

운영 자동화

Shell Script를 활용해 반복적인 운영 작업을 자동화하고 업무 효율과 정확성을 높입니다.

  • 배포 자동화
  • 백업 자동화
  • 로그 삭제
  • 상태 점검 · 재기동
06

장애 예방

사전 모니터링과 점검을 통해 장애 발생 가능성을 낮추고 안정적인 운영 환경을 유지합니다.

  • 모니터링
  • 로그 분석
  • 용량 관리
  • 패치 · 취약점 조치

INCIDENT RESPONSE

장애 대응 프로세스

장애 현상을 확인하고 원인을 분석한 후
서비스를 정상화하고 재발을 예방합니다.

01 장애 발생 이상 현상 인지
→
02 상태 확인 프로세스 · 서버 점검
→
03 로그 분석 ULOG · SLOG · TMLOG
→
04 원인 분석 문제 구간 및 원인 확인
→
05 정상화 조치 및 재발 방지
